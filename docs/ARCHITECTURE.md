# Architecture

PR Sift is a pnpm workspace with one app and one package.

```
packages/core        pure TypeScript, no DOM, no chrome.*, no Vue
apps/extension       the Chrome extension (Vue 3, Vite, Tailwind 4, shadcn-vue)
```

## Dependency rule

`apps/extension` depends on `packages/core`. `packages/core` depends on nothing in the repository. Browser APIs are
only touched in `apps/extension/src/lib/extension.ts` (storage) and `apps/extension/src/background` (network), so
everything else can be tested without a browser.

## packages/core

| Module       | Responsibility                                                      |
| ------------ | ------------------------------------------------------------------- |
| `diff`       | Parse GitHub patches into rows; build split rows; hash file content |
| `tree`       | Build the folder tree and collect files below a node                |
| `scopes`     | Smart filters: categories, repeated folders, folder grouping        |
| `extensions` | File type chips, including compound suffixes such as `.blade.php`   |
| `glob`       | Path patterns used by hidden-file rules                             |
| `notes`      | Note anchors, the prompt exported to an assistant, GitHub line URLs |
| `range`      | Multi-line note ranges                                              |
| `testing`    | Fixtures shared by tests (`@pr-sift/core/testing`)                  |

## apps/extension

- `content/` mounts the app inside a shadow root on `github.com` pull request pages (`main.ts`, `App.vue`).
- `background/` is the service worker that talks to the GitHub API and reads cross-origin text.
- `options/` is the settings page.
- `features/` holds one folder per feature. A feature owns its components, state (`use*.ts`) and tests:
  `diff`, `tree`, `filters`, `notes`, `review`, `appearance`.
- `components/ui/` is generated by the shadcn-vue CLI. Do not hand-edit it except for the documented portal patch.
- `lib/` is shared infrastructure: storage, settings, the portal target, keyboard isolation, shared types.

## Data flow

1. `usePullRequest` loads the pull request (`.diff` through the page session, the API as a fallback).
2. `useFileFilter` derives the visible files from filters, search, hidden rules and viewed marks.
3. `FileList` renders cards progressively; `DiffTable` renders rows and notes.
4. Settings, viewed marks and notes are stored in `chrome.storage.local`. Open reviews listen for storage changes.

## Why a shadow root

GitHub's CSS must not leak into the interface and ours must not leak out. Tailwind's `@property` rules are registered
on the document. Overlays teleport into a dedicated container inside the shadow root (`portalTargetKey`), never into
the element Vue patches.
